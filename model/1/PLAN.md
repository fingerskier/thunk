# Small Recursive Reasoning Diffuser — Implementation Plan

A phased build from a deterministic, TRM-style recursive core to a small **recursive reasoning diffuser** over text. The organizing thesis: spend compute on *iterations*, not *parameters* — the carried reasoning state and the denoising schedule are the same loop.

---

## Thesis & the one structural idea

A masked-diffusion answer is generated by repeatedly refining a partially-masked sequence. TRM already refines a carried answer `y` over up to 16 deep-supervision steps. **So make the supervision steps the denoising steps.** Each step takes a more-masked `y`, runs the recursion to update the latent reasoning state `z` and produce a less-masked `y`, and carries `(y, z)` forward. The diffusion timestep schedule *is* the supervision loop. This is what lets Phase 2 reuse the Phase 0/1 harness almost wholesale.

State you carry everywhere:
- `x` — embedded question (variable length).
- `y` — current answer (a token canvas; deterministic in P0–P1, partially-masked in P2+).
- `z` — latent reasoning scratchpad (the "thought" trace; never decoded directly).

One tiny network does both jobs; the job is selected by whether `x` is in the input (`z`-update sees `x`, `y`-update does not).

---

## Decisions to lock before writing code

These are the load-bearing choices that the TRM ablations say matter most. Get them wrong and you'll blame the architecture for a training bug.

1. **Backprop through the full recursion. Do NOT use the 1-step / implicit (DEQ) gradient.** TRM ablation: 1-step gradient → 56.5%, full backprop → 87.4%. Wiring in fixed-point iteration (TorchDEQ) made it *worse*. Fixed-point convergence is a fine intuition for what recursion does, a bad prescription for how to train it.
2. **Two carried features only: `y` and `z`.** One feature underperforms (forces the answer into `z`); more than two also underperforms. Two is the sweet spot.
3. **Gradient pattern per supervision step:** run `T−1` recursions inside `no_grad()` to silently improve `(y, z)`, then one recursion *with* gradients. Detach `(y, z)` between supervision steps (this is the residual-like mechanism that gives huge effective depth cheaply).
4. **Stabilizers are not optional on small data:** EMA of weights (0.999), stablemax loss, AdamW (β=0.9/0.95), warmup (~2k steps), small LR (1e-4), heavy weight decay (1.0 on tiny datasets, relax as data grows).
5. **Memory scales with `n` (the backprop'd recursion length), not parameters.** This is what OOMs, so `n` is your primary memory knob. The model itself is tiny.
6. **`y`-update is a pluggable head.** Implement deterministic (argmax) and diffusion (masked-token prediction) as swappable modules sharing the same recursion core. This is what makes the P1-vs-P2 comparison scientifically clean.

## Phase 0 — Reproduce the deterministic recursive core (de-risk the harness)

**Goal:** get the training dynamics under your hands on a known-good symbolic target before any text or noise enters.

**Build:**
- Tiny 2-layer net (self-attention variant; ~7M params, hidden 512).
- `latent_recursion(x, y, z, n)`: `for i in range(n): z = net(x, y, z)` then `y = net(y, z)`.
- `deep_recursion`: `T−1` no-grad recursions + 1 with grad.
- Deep-supervision loop (`N_sup=16`) with detach between steps.
- Simplified ACT halt head (binary "is current answer correct" CE; no Q-learning, no second forward pass).
- EMA + stablemax wired in from day one.

**Target task:** Sudoku-Extreme (1k train / 423k test) or Maze-Hard. Use the published augmentation (shuffles / dihedral).

**Success criteria:** within a few points of TRM's reported numbers (Sudoku ~85%+, Maze ~85%). If you're at ~56%, your gradient is flowing through only the last steps — fix that first.

**Compute:** single GPU (L40S/A100/4090-class), under ~2 days. Watch for overfit-then-diverge — that's the EMA/weight-decay signal, not an arch problem.

**Exit gate:** harness reproduces a known result. Do not proceed until this is green.

## Phase 1 — Move the recursive core to text, still deterministic

**Goal:** swap the grid for tokens while changing nothing else, so any new failure is attributable to the text plumbing alone.

**Build:**
- Tokenizer (start with a small byte-level or compact BPE; you can adopt a real pretrained tokenizer later).
- Variable-length question embedding for `x`; **fixed-length answer canvas** for `y` (this deliberately preserves TRM's fixed-output assumption — defer variable length to Phase 3).
- Keep deterministic argmax `y`-head, full CE loss, everything else identical to Phase 0.

**Target task (pick one, keep answers short and fixed-format):**
- Synthetic symbolic-text: list sorting, modular arithmetic, simple algebra, or **Countdown** (combinatorial arithmetic — good planning signal, used by LaDiR).
- Or fixed-format GSM8K-style answers where only the final numeric answer is the canvas.

**Success criteria:** exact-match accuracy clearly above an autoregressive baseline of similar parameter count on the same task. Record this number — it's the bar Phase 2 must beat to justify its complexity.

**Compute:** single GPU, ~1–2 days.

**Exit gate:** deterministic recursion works on tokens. You now have the baseline the diffuser must earn its keep against.

## Phase 2 — Make the answer generative (the diffuser) ← the novel core

**Goal:** replace the deterministic `y`-update with a masked discrete-diffusion update, fusing the denoising schedule into the supervision loop. This is the contribution: a ~10M-param recursive *reasoning diffuser*, a regime LaDiR demonstrated only at 8B.

**Build:**
- Forward (noising) process on the answer canvas: absorbing-state masking (`[MASK]`), masking probability tied to the supervision-step index via a schedule `t = schedule(s)`.
- Reverse: at each supervision step the model predicts all masked positions in parallel; keep high-confidence tokens, re-mask the rest at the next (lower) noise level, carry `(y, z)` forward.
- Loss: masked-diffusion cross-entropy on currently-masked positions (replaces the dense CE). Keep the halt head.
- Keep the gradient scheme and stabilizers exactly as P0/P1.

**Core training step (pseudocode):**
```python
for x_q, y_true in loader:
    x = embed_question(x_q)
    y = mask_all(canvas_like(y_true))     # start (near) fully masked
    z = z_init
    for s in range(N_sup):                # supervision steps == denoising steps
        t, t_next = schedule(s)
        with torch.no_grad():             # T-1 warmup recursions, no gradient
            for _ in range(T - 1):
                y, z = latent_recursion(x, y, z, n)
        y, z = latent_recursion(x, y, z, n)   # one recursion WITH gradients
        logits = output_head(y)
        loss  = masked_diffusion_ce(logits, y_true, masked_positions(y))
        loss += halt_bce(q_head(y), is_correct(logits, y_true))
        loss.backward(); opt.step(); opt.zero_grad(); ema.update(model)
        y = remask(argmax(logits), t_next).detach()   # carry less-masked answer
        z = z.detach()
        if q_head(y) > 0: break
```

**Success criteria (the experiment that matters):** on the *identical Phase 1 task*, compare deterministic-TRM vs recursive-diffuser on (a) pass@1 — must be ≥ the P1 baseline — and (b) pass@k / solution diversity, where the generative version should win decisively. If the diffuser can't at least match deterministic pass@1, the added machinery isn't paying for itself yet; debug the schedule and masking before scaling.

**Compute:** single GPU, several days (diffusion adds steps but the model is tiny).

**Risks specific to this phase:**
- Schedule design (how fast you unmask across the 16 steps) is fiddly; start with a simple linear/cosine schedule, ablate later.
- Confidence-based remasking can stall on hard positions — consider a small fixed unmask budget per step as a fallback.

## Phase 3 — Scale the text (variable length, longer reasoning, real benchmarks)

**Goal:** confront the things Phases 1–2 deliberately deferred.

**Build / decisions:**
- **The canvas / length problem** (the #1 text-specific risk). Options, roughly in order of effort: (a) pad to max length + learned EOS; (b) a length-predictor head; (c) **block / semi-autoregressive diffusion** (BD3-LM style) — denoise a block, condition the next block on it. (c) is the most robust for variable, longer outputs and is where I'd invest.
- Real datasets: GSM8K, a MATH subset, or your planning task at larger scale.
- **Test-time scaling:** sample multiple denoising trajectories and select by self-consistency or a reward/verifier. This is where the generative formulation earns real accuracy over deterministic.
- Move to a real pretrained tokenizer; possibly initialize embeddings from a small pretrained model.

**Watch carefully — the "smaller is better" finding may not survive here.** TRM attributes tiny-model superiority to *scarce data* and overfitting. As you add data and open-ended text, the optimal size very likely grows. Re-run the layers/recursion trade-off at this scale rather than assuming 2 layers holds. Treat model size as a hyperparameter you re-tune per data regime.

**Success criteria:** competitive pass@1 and a clear pass@k advantage on a real reasoning benchmark at a parameter count far below comparable autoregressive models.

**Compute:** 2–4 GPUs; multi-day runs.

---

## Phase 4 — Stretch: latent-thought diffusion + RL post-training

Only after Phase 3 is solid.

- **Diffuse over `z` (latent thoughts), not just the surface answer** — the LaDiR move. Encode reasoning steps into latent thought tokens (VAE), denoise those, decode the answer conditioned on them. This is where "reasoning in latent space" becomes literal and where the most interesting generalization gains have been reported.
- **RL post-training** (diffu-GRPO style) if you want to push beyond supervised refinement. Note: likelihood estimation for diffusion LMs is genuinely harder than for AR models — budget for that complexity.

Design the `heads` and `data/tasks` behind single interfaces so a phase transition is a config swap, not a rewrite.

## Cross-cutting risks (be honest about these up front)

- **Small + diffusion + open text is unproven.** Working diffusion LMs are billions of params; the tiny-recursion wins are on structured puzzles. You are explicitly trying to close that gap — negative results are a real possibility. The deterministic baseline at every phase is your insurance: it tells you whether a given step actually helped.
- **Parallel denoising can't shortcut genuinely sequential reasoning.** There's a formal sequentiality bottleneck (~log N steps) for masked diffusion. For deep multi-step arithmetic you may *need* many denoising steps or semi-AR blocking — don't expect parallelism to make sequential logic free.
- **The "2 layers is optimal" result is a small-data artifact.** Re-tune size as you scale data/text (Phase 3). Don't cargo-cult 7M.
- **Length is the text-specific tar pit.** Phases 1–2 dodge it on purpose; Phase 3 must solve it deliberately (lean toward block diffusion).
- **Memory OOMs come from `n`, not params.** Tune the backprop'd recursion length against your GPU early so you know your ceiling.

## Start here (first week)

1. Stand up the repo scaffold with pluggable heads/tasks.
2. Phase 0 on Sudoku-Extreme; reproduce a known number. **Do not move on until green** — this validates EMA + stablemax + detach + full-backprop interacting correctly.
3. Only then Phase 1 on one short-answer synthetic-text task, recording the deterministic baseline.

The exciting part is Phase 2, but the value of Phases 0–1 is that when Phase 2 misbehaves, you'll know it's the diffusion schedule and not your training harness — because the harness will already be proven.
